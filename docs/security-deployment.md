# API 보안 수정 적용 안내

## 변경 사항

- 브라우저는 Supabase 로그인 토큰으로 `/api/ai`, `/api/stock`만 호출합니다.
- Gemini 키는 서버의 `GEMINI_API_KEY`에서만 읽습니다. `VITE_` 접두사 비밀키는 사용하지 않습니다.
- 서버는 Supabase Auth로 토큰을 검증하고, DB의 원자적 `consume_api_quota`로 호출 제한을 검사합니다.
- 기존 인증 완료 계정만 API 허용 목록에 들어갑니다. 신규 계정은 운영자가 별도 승인해야 합니다.
- 주가: 계정별 분당 120회, UTC 하루 3,000회. AI: 분당 6회, UTC 하루 60회.
- 제한 저장소 오류나 미설정 시 503으로 차단합니다. 메모리 카운터로 우회하지 않습니다.
- 요청 메서드, 티커, AI 입력 크기, 출력 토큰 제한 및 외부 요청 타임아웃을 적용합니다.
- 로그인 계정이 바뀌면 가계부 화면 전체를 다시 마운트해 이전 코멘트와 지연 응답이 새 계정 화면에 섞이지 않도록 합니다.
- 개인 AI 코멘트 읽기/삭제/저장에도 명시적 `user_id`를 사용합니다.

## 배포 전 필수 순서

1. Supabase SQL Editor에서 현재 인증 완료 계정 목록을 검토합니다. 개인 앱의 정상 계정만 있는지 확인한 뒤 `supabase-api-security.sql`을 한 번 적용합니다. 이 파일의 허용 목록 초기화는 실행 시점의 인증 완료 계정을 포함하므로, 재실행 시 새 계정이 추가될 수 있습니다.
2. `api_allowed_users`에 실제 사용하는 계정이 들어갔는지 확인합니다. `api_request_counters`와 허용 목록은 브라우저 계정의 직접 읽기/쓰기를 허용하지 않습니다.
3. Vercel 프로젝트 `booboo-cgw8` 환경변수에 서버 전용 `GEMINI_API_KEY`를 설정합니다. 기존 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`는 서버에서도 읽을 수 있습니다. 서버 전용 별칭 `SUPABASE_URL`, `SUPABASE_ANON_KEY`를 설정해도 됩니다. Supabase service role 키는 필요하지 않습니다.
4. 노출된 Gemini 키를 새 키로 교체하고 기존 키를 비활성화합니다. 새 키도 `VITE_` 변수로 설정하면 안 됩니다. 브라우저를 통한 인증 키 생성/변경은 사용자가 직접 완료해야 합니다.
5. `VITE_GEMINI_API_KEY`를 모든 Vercel 환경에서 제거하고 새 버전을 배포합니다. 과거 배포 파일에 포함된 키도 있으므로 환경변수 삭제만으로 대응이 끝나지 않습니다.
6. 배포 후 비로그인 요청 401, 로그인 정상 요청, 제한 초과 429, 계정 전환을 확인합니다. 배포된 JS에서도 API 키 패턴이 없는지 확인합니다.

운영 DB migration과 서버 환경변수 설정 전에 main을 푸시하면 AI·주가 API가 503으로 차단됩니다. 먼저 설정을 완료해야 합니다.

## 확인 결과 (2026-09-11)

- `npm run build`, `npm run lint`, `npm test` 실행.
- 서버 인증, 허용 목록, quota 실패 시 차단, 429, 티커 검증, AI 입력 제한, 서버 오류의 키 비노출, 정상 텍스트/이미지 응답, React 계정 전환을 테스트합니다.
- 별도 PGlite 테스트 DB에서 SQL 실행, 분/일 제한, 기간 초기화, 타 계정 거부, 카운터 직접 수정 거부, 익명 RPC 거부를 검증했습니다.
- 로컬 배포용 JS에서 Google API 키 패턴, `VITE_GEMINI_API_KEY`, Google API 직접 호출 URL이 없음을 확인했습니다.
- 운영 DB 적용, 운영 환경변수 변경, Gemini 키 교체, 배포 후 확인은 아직 완료되지 않았습니다.

## 한계 및 패키지

- 이 제한은 인증된 계정의 외부 API 남용 방어입니다. 대규모 DDoS로부터 Vercel 함수 실행 자체를 보호하려면 플랫폼 방화벽 설정도 필요합니다.
- 개인 코멘트의 `type='person'`은 실제 DB의 `ai_comments` 타입 제약에 포함되어 있어야 합니다. 기존 로컬 기본 스키마는 bot/challenge만 기재되어 있으므로 운영 DB 제약을 확인해야 합니다. 이번 migration은 기존 재무 데이터나 이 제약을 변경하지 않습니다.
- 기존 운영 라이브러리 버전은 업데이트하지 않았습니다. 계정 전환 회귀 테스트용 `react-test-renderer`만 개발 의존성에 추가했습니다.
- 패키지 보안 업데이트는 외부 라이브러리의 취약 버전을 수정된 버전으로 교체하는 작업입니다. 별도 변경에서 호환성 확인과 빌드/테스트를 거쳐 적용합니다. `npm audit fix --force`를 그대로 실행하지 않습니다.
